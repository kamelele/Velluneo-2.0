# Maintaining the distributed toolkit

Read README.md, PACKAGE-MANIFEST.json and the relevant design guides before changes.
Project agents use templates/project/AGENTS.md and the linked workflow/role documents.
Do not mistake synthetic fixture approvals or tabletop walkthroughs for actual people,
agent executions, physical measurements or product/process qualification.

Preserve rule basis, numerical limits, truthful pin types and scoped exception review.
Do not relax global checks to hide violations. New automatic CAD behavior needs actual
KiCad positive and negative cases. Pin exact KiCad and toolkit inputs in project work.
Run the selected unit/CAD/example suites with scripts/validate_candidate.py in a
disposable copy and retain actual results, source hashes, skips and limitations.

Edit public proposals through reviewable branches/PRs. Maintainers integrate accepted
contributions into their canonical development sources before public release, retaining
author attribution. Contributors need no access to those private sources. Publication
must preserve accepted public changes and use reviewed, versioned exported files.
Do not include customer projects, private inventories, credentials or local caches.

This is a review candidate. Consult LICENSE, NOTICE, LICENSES/README.md and
THIRD_PARTY_NOTICES.md for license scope; the manifest records remaining package/
publication review and is not design-stage approval. Write toolkit
documentation, templates, issues and contributions in English.
